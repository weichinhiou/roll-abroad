## 二、讀懂的重點（與卡片有關的）

**出發前**
- 公假：因公派員出國，**出國前 45 天**向**人事室**上簽。附：人事室申請表（出國參加國際會議申請表、出國經費預計支用表）、會議議程、邀請函／大會同意函／接受函（**含中文翻譯**）、論文摘要。

- 保險：依外交部共同供應契約辦理，**機關為要保人**，不能自行投保再報銷。
- 規則 12：公假要求論文為第一作者。**機器人規則寫明「不要主動提，有問才答」，也不要鼓勵走特例**，所以我不做這個主題的卡。

### 評估：「只追收穫就是高張力結局」合理嗎？（Jean 要求一起評估，2026-11-06）

方法：1,000 局，三種模擬玩家（都用現在的 84 張），統計結局與「資源耗盡次數」（`strain`）。

| 玩家 | 結局 | 耗盡 0／1／2／3／4／5+ 次 |
| :-- | :-- | :-- |
| 只挑收穫最高、不看資源條 | wild 665、steady 307、stage 27、safe 1 | 188／147／229／227／123／86 |
| 同上但會看資源條 | steady 846、stage 137、wild 17 | 856／127／16／1／0／0 |
| 完全隨機 | steady 489、wild 213、safe 144、stage 154 | 640／147／106／67／28／12 |

**結論**
1. **機制本身合理**：遊戲是「有限資源下取捨」，追收穫不顧資源就該付代價。介面已把剩 2 以下的資源標成 `low`（`render.js:157`，外觀沒實際看）。看資源條的玩家 86% 不耗盡，說明這個懲罰是可以避免的，不是無解。
2. **真正的問題是另一頭**：會看資源條的玩家 **85% 都是 steady**，safe 和 wild 幾乎消失。四個結局其實只是「放任／亂選／會管理」三種玩法的名次，聰明玩家只會看到一種結局，重玩沒有分歧。
3. **wild 的措辭是正面的**（「高張力完成者：幾度差點走不下去，但你還是走完了」），不像處罰，這點沒問題。
4. **文件與程式對不上**：plan D14 寫「中途資源耗盡過或最低資源 ≤1 → wild」，`engine.js` 實際是「耗盡 ≥ 2 次 → wild」，門檻較寬。哪個才是本意沒人確認過。
